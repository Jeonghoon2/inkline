# 데이터 엔지니어 — 이력서 패턴

## 성과 고르기·순서
1. 파이프라인 하나를 끝에서 끝까지(수집 → 저장 → 검사 → 제공) — 규모·주기·정합성 숫자
2. 대용량 처리 문제(메모리·시간)와 해결 숫자
3. 데이터 품질·정합성: 이상 데이터 발견·정리, 건수 대조, 품질 검사 수
4. 읽기 경로 최적화(레이크에서 읽기, 실행 계획)
5. 거버넌스: 보관 기간, 삭제, 개인정보 비식별, 리니지
- 화면·UI 작업은 리니지처럼 데이터 흐름을 보여 주는 것만

## 문장 꼴
- `**주문 기록 매일 S3 보관 파이프라인**: 하루치를 날짜별 Parquet(Hive 식 분할)로 올리고 오래된 DB 기록 정리, 옮긴 건수 = DB 건수`
- 오케스트레이터가 Airflow 가 아니면 실제로 쓴 도구 이름(예: 클라우드 예약 작업 + 컨테이너 작업)을 쓴다

## 기술 구역
- 언어·SQL / 저장·형식 / 처리·스케줄 / 클라우드·IaC / 품질·검증 — 공고 단어 순서, 안 쓴 Spark·Airflow 는 빼고 '보완할 경험'으로

## 간단 소개(2~4줄)
- "운영 데이터를 잃지 않고 옮기고 검증하는 데이터 엔지니어" + 대표 수치(예: 120만 건 무손실 이관, 메모리 75% 절감) + 백엔드 경험
