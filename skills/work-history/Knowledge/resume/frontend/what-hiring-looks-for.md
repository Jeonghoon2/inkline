# 프론트엔드 — 채용이 보는 것

## 핵심 정리
- **React + TypeScript 실무**는 거의 모든 국내 공고의 기본(요기요·엘리스·검색 표본). 차이는 그 위에서 무엇을 **주도**했는가 — 엘리스는 "아키텍처, 상태 관리, 컴포넌트 설계를 주도한 경험"을 자격요건으로 둔다
- **지표로 말하는 성능**: 엘리스는 Web Vitals·p95 지연·오류율로 번들·렌더링 병목을 진단·개선하는 일을 주요업무로 둔다. Core Web Vitals 기준은 LCP ≤ 2.5초, INP ≤ 200ms, CLS ≤ 0.1(75백분위, web.dev)
- **디자인 시스템·공통 컴포넌트**: 구름은 React·TypeScript·Storybook·번들러(Webpack/Rollup)와 디자인 시스템 운영 경험을 요구
- **접근성·웹 표준·반응형**은 우대로 자주 나온다(케이티피 검색 요약, 해외 공고 공통)
- 2026년 공고의 새 흐름: **AI 도구로 생산성 개선**과 **LLM 기능을 제품에 넣기**(엘리스)
- 이력서·포트폴리오에는 "숫자로 표현한 성과"와 실제 개발 경험을 넣으라고 공고가 직접 요구(엘리스 참고사항)

## 하기 / 하지 않기
- 하기: 사용자가 겪던 불편 → 바꾼 화면 → 사용자에게 달라진 것(숫자) 순서
- 하기: 결함 재현 방법(실서버 데이터·프레임 기록)과 회귀 점검 규모를 함께
- 하지 않기: 화면 목록 나열("~ 화면 개편" 10줄) — 묶어서 한 줄, 숫자 있는 것만 위로
- 하지 않기: 쓰지 않은 상태 관리·테스트 도구 이름

## 키워드
React, TypeScript, 상태 관리(Zustand 등), 컴포넌트 설계, 디자인 시스템, 코드 분할, 지연 로딩, 번들 크기, Core Web Vitals(LCP·INP·CLS), 렌더링 최적화, 접근성(WCAG·키보드), 반응형, 테스트(단위·E2E), 계약 검사, CI/CD, CDN 배포, Vite
