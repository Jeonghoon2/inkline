# 프론트엔드 — 이력서 패턴

## 성과 고르기·순서
1. 성능 숫자(번들·시작 코드·렌더링 메시지·CLS) — 전 → 후
2. 사용자에게 보이던 결함을 재현해 없앤 일(재현 방법 + 0건 확인)
3. 구조 설계: 화면과 서버 계약 검사, 오류 경계, 공용 부품·테마 토큰
4. 품질 체계: 단위 테스트 수, 화면 상태 회귀 점검 수, CI·CDN 배포
5. 운영 화면 개편은 묶어서 한 줄(사용자 문제 → 바뀐 점)

## 문장 꼴
- `**시작 시 읽는 화면 코드 40% 경량화** (2.0 → 1.2MB): 첫 화면에 필요 없는 화면을 처음 쓸 때 불러오도록 분리`
- 접근성은 따로 구역을 만들기보다 성과 줄의 '어떻게'에(키보드 조작, 움직임 줄이기, 색 대비 수치)

## 기술 구역
- 6~10개로 짧게(BeamJobs): 언어 / 프레임워크·상태 / 스타일 / 빌드·테스트 / 배포
- Electron 같은 데스크톱 기술은 '데스크톱 앱' 분류로 따로 — 웹 직무 독자가 헷갈리지 않게

## 간단 소개(2~4줄)
- "성능과 결함을 숫자로 재고 고치는 프론트엔드 개발자" + 주력 스택 + 대표 수치
