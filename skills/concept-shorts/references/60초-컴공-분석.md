## 화면
- 1080×1920 검은 바탕, **컷 전환 0회** — 한 화면에서 요소가 나타나고·색이 바뀌고·움직이기만 한다(수식 글꼴로 보아 Manim, 추정)
- 3단 고정: 위 제목(개념 이름, 끝까지 고정) + **한 줄 요점 띠**(빨강 문제 · 노랑 핵심 · 초록 해결) / 가운데 그림 하나 / 아래 두 줄 자막(말 그대로) / 왼쪽 아래 채널 로고
- 마지막: 제목이 '시간복잡도'로 바뀌고 큰 노란 O(…) 결과 카드 → "더 많은 CS 지식은 '60초 CS'에서 만나요" 고정 엔딩

## 대본 6박자
1. 문제(0~10초): 상황 + 단순한 방법의 한계 ("자리마다 비교하면 최악엔 O(nm)") — 2편만 정의 + 비유(응급실)로 시작
2. 핵심 아이디어 한 문장 ("해시값을 원 위에 놓아요")
3. 작은 실제 예를 한 걸음씩 — 따라 셀 수 있는 크기(원소 3~8개), 진짜 숫자(x=3.5, 265 → 65 → 650 → 653)
4. 반전 "다만…" ("서버가 한쪽에 몰리면 → 가상 노드", "979도 해시가 4 → 충돌")
5. 실무 연결 ("OS 작업 스케줄러", "실제로는 998244353")
6. 결과 카드 + 체감 숫자 ("100만 개가 기다려도 20걸음") + 고정 엔딩

## 말·그림 규칙
- 해요체, 한 문장 2~4초, 한 문장 = 자막 하나. 용어는 처음 나올 때 한 문장 정의("이 숫자를 해시라고 해요")
- 한 대상 = 한 색(서버 S1 파랑 → 맡은 키도 파랑), 보는 곳 = 노란 테두리, 버린 것 = 흐림
- 전후를 같은 화면에서 바꿔 보여 준다(나머지 방식 상자 → 원)
- 자막(말)과 띠(요점)가 따로 — 소리 없이 띠만 읽어도 흐름을 안다

## 약점 → 우리 쇼츠에서 바꾼 것
- 5편 중 3편이 60초 초과(76~85초) → 대사 합 360~430자·박자 12~16개(50~58초), 음성 길이 60초 넘으면 다시 쓰기. 처음엔 340자로 잡았다가 30~45초에 사실만 늘어놓는 대본이 되어 늘렸다(2026-10-13). 그 뒤 말 속도를 185로 늦추면서 대사 합 목표 350자(상한 370자)·박자 11~14개로 다시 맞췄다

- 면접 연결 없음 → 엔딩을 사전의 꼬리 질문으로(답은 기록 상세 창에서)
