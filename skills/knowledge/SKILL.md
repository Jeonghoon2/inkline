# 지식사전 (~/My-History/knowledge)

찾은 근거를 버리지 않고 분류해 두었다가, 다음 작업에서 분류로 찾아 참고하고 '어떤 근거를 썼는지'를 설계 문서 · 작업 기록 · 주간 보고에 남기기 위한 저장소다. Inkline 앱의 '지식사전' 탭이 같은 폴더를 보여 주고 고친다.

## 폴더

```
~/My-History/knowledge/
  INDEX.md                    자동 생성 목차 — 손으로 고치지 않는다
  <분류>/<slug>.md            자료 하나 = 파일 하나
```
- 분류 = 폴더 이름(주제, 한국어 가능 — 예: 학습 과학, LLM · 프롬프트, 데이터 엔지니어링, UI · UX, 보안). **새 분류를 만들기 전에 INDEX.md 의 분류에서 먼저 고른다**
- 분류 · slug 에 `/ \ :` · 괄호 `( )` · 맨 앞 점 · 제어 문자는 쓰지 않는다. 80자 이하 (괄호가 있으면 `(지식사전: …)` 링크가 끊긴다)
- **길이 한도**(앱에서 고칠 때 막힌다): 제목 200자 · 출처 300자 · 요약 500자(한 줄) · 태그 8개 · 태그 하나 30자 · 주소 2000자(http/https)
- slug: 제목에서 영문 · 숫자 · 한글만 남기고 공백은 `-`, 소문자, 60자 이하. 겹치면 `-2`, `-3`

## 언제 읽나
- **스스로:** 새 기능 설계 · 방식 고르기 · 도메인 규칙(학습 · 보안 · 접근성 · 법 · 운영 · UX 등)이 걸린 작업을 시작하기 전
- **하지 않음:** 작은 수정 · 오타 · 단순 질문 · 이미 정해진 일을 그대로 하는 작업
- **요청:** 사용자가 "지식사전 참고해서", "<분류> 보고" 라고 하면 언제든

## 어떻게 읽나
1. `~/My-History/knowledge/INDEX.md` 에서 맞는 분류 · 태그 · 요약을 찾는다
2. 필요한 항목 파일만 연다(핵심 내용 · 쓰인 곳)
3. 쓴 자료는 설계 문서 · 작업 기록의 근거 줄에 `(지식사전: <분류>/<slug>)` 로 남기고, 그 항목 파일의 `## 우리 작업에 쓴 곳` 에 한 줄 더한다(아래 '쓰기' 4번)

## 언제 쓰나
- 작업 중 논문 · 메타분석 · 지침(공식 스타일 가이드 · 표준) · 사례(다른 회사 · 서비스의 실제 사례) · 책 · 공식 문서를 찾아 **판단의 근거로 썼을 때**
- 넣지 않는 것: 단순 API 사용법 확인, 오류 메시지 검색, 라이브러리 버전 확인처럼 판단 근거가 아닌 조회

## 어떻게 쓰나
1. INDEX.md 에서 같은 출처(주소가 같거나 제목이 같은 것)를 먼저 찾는다
2. 있으면 새로 만들지 않고 그 파일의 `## 우리 작업에 쓴 곳` 에 한 줄만 더한다
3. 없으면 아래 형식으로 새 파일을 만든다(있는 분류 먼저)
4. '쓴 곳' 줄: `- <YYYY-MM-DD> <프로젝트> — <무엇에 썼나> (<작업 기록 파일 상대 경로>#<날짜>)` 예: `- 2026-10-17 ShopAPI — 결제 재시도 설계 (ShopAPI/2026-10.md#2026-10-17)`
5. 끝나면 목차를 다시 만든다: `node ~/.claude/skills/knowledge/index.mjs` (형식 오류가 있으면 출력에 나온다 — 고친다)

```markdown
# <제목 — 원문 그대로>
- 종류: 논문 | 메타분석 | 지침 | 사례 | 책 | 문서 | 기사
- 출처: <저자> · <연도> · <학술지 · 출판사 · 기관> · <쪽 · 절 · 장 — 모르면 '쪽 미확인'>
- 주소: <URL — 없으면 이 줄을 뺀다>
- 원문: <slug>.pdf — 원문 PDF 를 항목 옆(같은 분류 폴더)에 보관했을 때만
- 태그: <a, b, c>
- 요약: <한두 문장, 한국어>
- 추가: <YYYY-MM-DD> · <Claude | Codex | Gemini | 나>

## 핵심 내용
- <요점 — 가능하면 쪽 · 절 · 표 번호와 함께>

## 우리 작업에 쓴 곳
- <위 4번 꼴>

## 메모
- <자유 — 한계(대상 연령 · 표본), 원문 대조 여부, 우리와 다른 점>
```
- 필수: 제목 · 종류 · 출처 · 요약. 나머지는 없으면 섹션째 뺀다
- **PDF 논문:** PDF 를 받았거나 찾았으면 쪽 단위로 읽고(Claude Code 는 Read 의 pages 로), 핵심 내용 줄마다 근거 쪽을 `(p.N)` 으로 붙인다 — PDF 파일의 쪽 번호 기준. 학술지 인쇄 쪽 범위(pp. 989–998)가 보이면 출처 칸에 그것을 쓴다. 원문 PDF 는 `<분류>/<slug>.pdf` 로 복사해 두고 머리에 `- 원문: <slug>.pdf`. 글자를 뽑을 수 없는 스캔본이면 초록 · 본문을 직접 읽은 범위만 적고 메모에 '스캔본'
- **제목을 모를 때:** 저자 · 연도만 알면 제목을 `<저자> <연도> (제목 미확인)` 으로 적는다. 기록이 효과 이름 하나로 논문 여럿을 묶어 인용하면(예: 'Pretesting effect'(A 2009, B 2009)) 그 이름이 어느 논문의 제목인지 확인될 때만 제목으로 쓰고, 나머지는 '제목 미확인' + 태그에 효과 이름
- **출처 칸:** `저자 · 연도 · 학술지/출판사/기관 · 쪽` 에서 모르는 칸은 뺀다(학술지를 모르면 그 칸째 생략). 쪽만 모르면 '쪽 미확인'. 저자를 '외'로만 알면 `Fyfe 외` 처럼 그대로 적는다(전체 저자 미확인이라는 뜻)
- **종류 고르기:** 실험 · 조사 · 인터뷰 · 리뷰 논문 → 논문 / 여러 연구를 묶은 통계 분석 → 메타분석 / 표준 · 가이드 · 체크리스트(OWASP, WCAG, 스타일 가이드) → 지침 / 다른 회사 · 서비스의 실제 적용기 → 사례 / 단행본 → 책 / 공식 제품 · 기술 문서 → 문서 / 뉴스 · 블로그 → 기사
- **쓴 곳 줄:** 프로젝트 = 작업 기록의 카테고리 폴더 이름, 앵커 = 그 기록 파일의 `## 날짜` 제목. 같은 날 기록이 여럿이면 무엇에 칸 앞에 기록 제목을 붙인다: `- 2026-10-17 ShopAPI — 결제 중복 방지: 멱등 키 보관 기간 (ShopAPI/2026-10.md#2026-10-17)`
- **원문 대조:** 개별 결과를 알면 메모에 '원문 대조함' · '초록만 봄' · '출판사 차단'. 기록이 집계만 주면 그 집계를 그대로 적고 '개별 결과는 기록에 없음'
- 태그는 2~5개, 메모는 평서체('~다') 짧은 문장
- **지어내지 않는다:** 쪽 · 연도 · 학술지 · 수치는 확인한 것만. 모르면 '쪽 미확인' · '연도 미확인'. 원문을 직접 열어 대조했는지 메모에 적는다(예: '원문 대조함' · '초록만 봄' · '출판사 차단으로 못 엶')
- 남의 문장을 길게 옮기지 않는다 — 요약하고, 꼭 필요한 인용은 한 문장 안팎
- 개인정보 · 비밀번호 · 토큰 · 사내 비공개 문서 내용은 넣지 않는다

## 다른 스킬과
- work-history: 근거를 참고한 작업의 수행 일지 줄 끝에 `(지식사전: <분류>/<slug>)` 를 붙인다. Inkline 주간 보고가 그 항목의 출처(저자 · 연도 · 쪽)를 끌어와 '채택 … (근거: …)'에 쓴다
- 이력서 자료(work-history 의 `Knowledge/resume`)는 이 지식사전과 따로 둔다
