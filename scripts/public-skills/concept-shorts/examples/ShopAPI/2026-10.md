## 2026-10-27

### 트러블슈팅 — 야간 정산 작업이 메모리 부족으로 멈춘 문제 해결
- 종류: 트러블슈팅
- 분류: 백엔드 - 배치, 백엔드 - PostgreSQL, 성능 - 메모리
- 내용: 매일 새벽 정산 작업이 중간에 죽었다. 하루치 주문 32만 건을 한꺼번에 읽다가 메모리를 넘긴 것이 원인이어서, ==5천 건씩 나눠 읽도록|나눠 읽기(스트리밍)== 바꿨고 최대 메모리가 540MB에서 135MB로 줄었다.

#### 상황
- 매일 새벽 2시에 도는 정산 작업, 하루 주문 약 32만 건
- 처음 실행이라 쌓인 날짜를 하루씩 차례로 정산하던 중이었다

#### 문제
- 작업이 11일째 날을 처리하다 오류 없이 꺼졌다. 종료 코드 137은 시스템이 메모리 부족으로 강제로 끈 경우의 번호다(상한 1GB)

#### 해결 과정
1. **원인 찾기** — 종료 코드와 메모리 그래프로, 하루치 32만 건을 통째로 올리는 구간을 좁혔다.
2. **해결 방법 고르기** — 메모리 증설은 비용이 계속 들고 데이터가 늘면 다시 넘친다. 결과를 DB에 둔 채 5천 건씩 꺼내는 서버 쪽 커서로 나눠 읽기로 했다.
3. **수정** — 5천 건씩 읽고 처리한 뒤 버리고, 멈춘 날부터 이어 하도록 했다.
4. **효과 측정** — 같은 1GB 상한에서 최대 메모리 540MB → 135MB.

#### 고민한 흔적
- 서버 쪽 커서는 다 읽을 때까지 트랜잭션을 붙잡는다. 정산 한 번이 몇 분이라 괜찮다고 봤다(추정).
